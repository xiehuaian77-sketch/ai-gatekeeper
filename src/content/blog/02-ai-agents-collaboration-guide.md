随着大语言模型（LLM）推理能力的持续提升，软件开发的范式正在经历从 **Prompt Engineering（提示词工程）** 向 **Agentic Workflows（智能体工作流）** 的深刻演变。

## 1. 为什么单一 Prompt 不足以应对复杂任务？

在面对多步骤、长链路的工程问题（如自动化代码重构、全流程测试与漏洞排查）时，单一的单次对话请求存在明显局限：

- **无法自我验证**：缺乏对生成代码或方案的即时验证和语法检查；
- **状态丢失**：无法维护复杂的执行树与上下文分支；
- **工具调用缺乏反馈闭环**：一旦某个步骤出错，无法自主回滚并修正策略。

## 2. 智能体架构四大核心支柱

一个健全的 Agentic 架构通常由以下四个模块组成：

```
+-------------------------------------------------------------------+
|                        Orchestrator Agent                         |
|   (任务分解 Task Decomposition & 规划 Planning)                   |
+-------------------------------------------------------------------+
       |                                              |
       v                                              v
+-----------------------+                    +----------------------+
|     Research Agent    |                    |     Coding Agent     |
|   - 检索代码与文档     |                    |   - 生成与修改代码    |
|   - 语义分析与依赖关系 |                    |   - 工具链调度       |
+-----------------------+                    +----------------------+
       |                                              |
       +--------------------->  [ VERIFY ]  <---------+
                                     |
                                     v
                        +--------------------------+
                        |     Execution & Test     |
                        |   - 静态分析 / 单元测试   |
                        |   - 反思与自我修复循环   |
                        +--------------------------+
```

### 1. 任务规划与拆解（Planning）
将宏观目标细分为可验证的原子任务（Atomic Steps），并在每一步前明确输入与预期产出。

### 2. 工具调用协议（Tool Use）
通过规范的 JSON Schema 定义外部工具（如文件读写、Bash 命令、API 查询），让模型能够安全可控地操作环境。

### 3. 反思与自我修正（Reflection & Self-Correction）
在工具执行完毕后，分析输出结果与报错日志，自主进行针对性的修复，而非直接向用户抛出异常。

## 3. 实战总结

自主智能体并非替代人类工程师，而是充当高智力的 **Pair Programmer（结对编程伙伴）**。设计优秀的智能体系统，关键在于建立清晰的边界、确定性的验证机制与结构化的信息流。
